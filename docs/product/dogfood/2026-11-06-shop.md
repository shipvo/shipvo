# Dogfood 2026-11-06: a small shop with mobile money and order tracking

**Persona:** a non-technical founder working only through an AI agent.
**App:** "My Shop", from `shipvo init myshop --name "My Shop" --template shop`. I added a fingerprint confirmation before payment, an "Orders" screen with four stages (Paid, Preparing, On the way, Delivered), and a notification when the order is confirmed. I added a product by editing `src/data/products.json` only.
**Device features:** payments (mobile money), biometrics (confirm payment), notifications (order confirmed).
**Code under test:** `main` at ac62282. Packages built from source, packed with `pnpm pack` into `/tmp/agent/tarballs/`, installed into `/tmp/agent/app/myshop` with npm `overrides`. Runner: GitHub Actions Linux, Node 22.23.4.

Caveat on honesty: the agent here wrote the code, as a founder's agent would. A real founder would not read it. I did not hand-edit anything beyond what an agent would do.

## What worked

- `shipvo init --template shop` gave a working cart, product pages and a mobile money payment with the right currency handling. All 4 starter tests passed on the first run.
- `doctor` was clear: 10 PASS lines.
- Driving over MCP worked at the first try. The tree has stable refs, the fingerprint dialog and the notification appear in the tree, and `device_log` marks each entry `simulated`.
- `end_session` returned the placed order with product ids, quantity and receipt.
- `set_device` for biometrics and payment made the failure path easy to test: `biometrics.nextResult: "fail"` gave "Payment cancelled", the cart stayed.
- `@shipvo/test` worked for new flows with no extra setup: the 2 tests I added passed on the first run.
- A second `shipvo sim` prints `Port 4545 is in use. Stop the other \`shipvo sim\` or pass --port <n>.` That is plain and correct.
- `publish --dry-run` printed plain English, built and signed release 1 and 2 in about 20 s each.

## Friction

### 1. `shipvo sim` crashes on a fresh app: the sim tarball omits two modules (issue #904)

Command: `npm run sim`

```
Exported: sim-dist
node:internal/modules/esm/resolve:275
  code: 'ERR_MODULE_NOT_FOUND',
  url: 'file:///tmp/agent/app/myshop/node_modules/@shipvo/sim/network-profiles.mjs'
```

Expected a running simulator. `npm test` then fails with `ECONNREFUSED 127.0.0.1:4545` and every MCP call has nothing to talk to. `packages/sim/package.json` `files` lacks `network-profiles.mjs` and `apps.mjs`. I confirmed with `tar tzf`. Workaround used: copy both files from `packages/sim/` into `node_modules/@shipvo/sim/`. This blocks every new user until the next release of `@shipvo/sim` that includes them. No test catches it today.

### 2. `npm run typecheck` fails on a fresh app (issue #905)

```
node_modules/@shipvo/runtime/src/install.ts(34,63): error TS2769: No overload matches this call.
  Argument of type 'Uint8Array<ArrayBufferLike>' is not assignable to parameter of type 'BufferSource'.
node_modules/@shipvo/runtime/src/install.ts(35,74): error TS2345: ...
```

Zero errors in app code. The runtime ships `.ts` source, so the app compiler checks it. The 2026-11-05 report recorded a clean `tsc --noEmit`, so this may be new; I did not bisect.

### 3. `publish --dry-run` prints an unexplained line (issue #909)

```
listing: assets/icon.png not found, skipped
Dry run complete. Nothing was sent.
```

`init` writes `listing.icon: "assets/icon.png"` and never creates the file. The app is private, so the line only worries a founder.

### Smaller points (no issue filed)

- **Rollback cannot be rehearsed offline.** `shipvo rollback --to 1 --dry-run` prints `Nothing to publish with. Hosted: run \`shipvo login\`...`. The docs say so honestly. It is already reported as #892 (closed today), and I did not re-test on a newer `main`.
- **Tap result can show a stale state.** After tapping "Use fingerprint" the returned tree said `Paying...`. The order was placed a moment later (`screen` showed "Order placed"). An agent that trusts the tap result would report a pending payment. Closed issue #463 covered this; the tool output does not say "call screen again".
- **`end_session` fields look odd** when each MCP call runs in its own process: `"app": "m1"` (the session name, not "myshop"), `"steps": 0`, `"seconds": 0`. I ran each batch in a separate process, so this may be my setup.
- **Orphaned simulator server.** After I stopped `shipvo sim` by killing its processes, `server.mjs` (pid 5290) still held port 4545 until I killed it by pid. I did not reproduce it with a clean Ctrl-C.
- **`/health` is a 404 on the simulator.** `doctor` and the docs do not name a ready check; `/app/` answers 200. This is what cost me 7 minutes.
