# Dogfood 2026-11-05: habit tracker with a biometric lock

**Persona:** a web developer new to mobile. Knows React and npm, has never used React Native or Shipvo.
**App:** "Habit Lock". A fingerprint lock screen, then a habit list: add a habit, check in, see the day streak, set a reminder notification.
**Code under test:** `main` at e2355fa. Packages built from source and packed with `pnpm pack` into `/tmp/agent/tarballs/`, then installed into `/tmp/agent/app/habits` from the tarballs.
**Device features used:** biometrics (unlock) and notifications (reminders). Two of the five in `docs/device-api.md`.

## What worked

- `shipvo init` + `npm install` + `npx playwright install chromium` + `npm run sim` worked as `getting-started.md` says, first time. `shipvo doctor` printed 5 PASS lines.
- `shipvo init` prints next steps that match the docs.
- The simulator served my screens as an accessibility tree. The fingerprint dialog appeared in the tree (`dialog "Confirm with fingerprint"` with `Use fingerprint` and `Cancel`).
- Local `@shipvo/mcp` now lists the app the simulator serves: `habits: Habit Lock. The app this simulator serves.` (issue #25 is fixed). `open_app("habits")` worked with `PN_SIM` only.
- A stale ref gave a clear error and the current screen: `Error [stale_ref]: stale ref e6: the screen changed. Take a new snapshot ...`.
- `@shipvo/test` read well. The failure-path test (fingerprint fails, app stays locked, `My habits` not shown) passed first time.
- `shipvo publish --dry-run` works offline and writes bundle, pointers (`b0`, `b1`, `b2`), release record and web export. `shipvo verify` on a pointer said `valid`. My edit to `src/release.ts` was in the web export (grep found it).
- `shipvo mcp` printed the local config when signed out.

## Friction

### 1. Scaffold tests fail the moment you replace the starter screen (fixed in this PR)

The first `npx vitest run` after I replaced `App.tsx`:

```
Test Files  1 failed | 1 passed (2)
     Tests  5 failed | 2 passed (7)
Error: nothing on screen matches "Use my location"
Screen now:
  - heading "Habit Lock" [level=1] [ref=e4]
  - generic [ref=e5]: Your habits are private.
  - button "Unlock with fingerprint" [ref=e6]
```

The error is accurate, but nothing in `getting-started.md` says `tests/app.test.ts` tests the starter screen. A newcomer replacing `App.tsx` will see red tests they did not write. I added one sentence to the doc. I deleted nothing: I ran only `tests/habits.test.ts`.

### 2. `device_log` on an unknown session returns an empty log (issue #194)

```
## device_log {"session":"m1"}
{ "note": "Everything here is simulated: ...", "log": [] }
## screen {"session":"m1"}
Error: no session 'm1': call /session first ...
```

I made this mistake myself: I assumed I could choose the session id, but `open_app` returns it (`habits-mw3h2i14`). Every other tool errored clearly. `device_log` said the app did nothing. Cause: `packages/mcp/src/server.ts:166` does not check `ok`.

Also seen: after `tap` opened the fingerprint dialog, `device_log` had an empty `log`. I did not check whether prompts are logged before they are answered, so I make no claim.

### 3. Rollback cannot be tried offline

`shipvo rollback --to 1 --dry-run`:

```
Nothing to publish with. Hosted: run `shipvo login`, then `shipvo app create` (or set SHIPVO_PUBLISH_TOKEN). Self-hosted: set CLOUDFLARE_ACCOUNT_ID, CLOUDFLARE_API_TOKEN and SHIPVO_KV_ID.
```

This matches the doc ("It still needs access to the control plane or KV"), so it is not a bug. I did not run a rollback, and I did not log in or use a token because the only reachable control plane is production. **Not proven:** rollback, patches (none are built in a dry run) and a real publish.

### 4. The measured times in `getting-started.md` read as the whole path (fixed in this PR)

The doc says `publish --dry-run` took 107 ms. That run uses `--skip-export`. With the real export, on this runner:

| Command | Time |
| --- | --- |
| `shipvo publish --dry-run` (first run, cold Metro cache, prints `Bundler cache is empty, rebuilding`) | 18.8 s |
| `shipvo publish --dry-run --skip-web true` | 12.0 s |
| `shipvo publish --dry-run` (second run) | 18.4 s |

The doc does say export was not timed, but a newcomer will think the command is instant. I replaced the sentence with these numbers. Also: `--skip-web true` saves about 6 s, so "run faster" is true but small.

### Smaller notes (no issue)

- The dry run prints `web artifact: 2 files at /w/habits/r1/`. That is a path inside the output folder, but it looks like an absolute path. The real file is `.shipvo/dry-run/w/habits/r1/`.
- `vitest` prints `The CJS build of Vite's Node API is deprecated` on every run.
- `--skip-web` needs a value (`--skip-web true`). A bare `--skip-web` is easy to type. I did not test what it does.
