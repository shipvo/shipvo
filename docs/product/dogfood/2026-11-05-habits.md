### Friction

#### 1. `shipvo publish` fails on a fresh app (issue #332)

```
Android Bundling failed 6418ms index.ts (625 modules)
Unable to resolve "expo-contacts" from "node_modules/@shipvo/device/src/index.ts"
...
shipvo: Command failed: npx expo export --platform android --output-dir dist-ota --clear
Run 'shipvo doctor' to check your setup, or set SHIPVO_DEBUG=1 to see the full error.
```

Without `SHIPVO_DEBUG=1` the user does not see the module name. `doctor` passes. The simulator and the tests pass, so the app looks fine until the first publish. This was my main blocker, and it is a regression: run 1 published on `main` at e2355fa. Cause: `@shipvo/device` requires `expo-contacts`, `expo-calendar` and `expo-document-picker` inside arrow functions, which Metro cannot treat as optional, and `shipvo init` does not install them. Workaround that I ran: `npm i expo-contacts@~58 expo-calendar@~58 expo-document-picker@~58`, then the dry run completed. The sim test suite cannot catch this because the simulator swaps the modules by alias.

#### 2. Rollback still cannot be tried offline

`shipvo rollback --to 1 --dry-run`:

```
Nothing to publish with. Hosted: run `shipvo login`, then `shipvo app create` (or set SHIPVO_PUBLISH_TOKEN). Self-hosted: set CLOUDFLARE_ACCOUNT_ID, CLOUDFLARE_API_TOKEN and SHIPVO_KV_ID.
```

Matches the docs, so not a bug. Same as run 1. I did not log in, because the only reachable control plane is production. **Not proven:** rollback, patches, a real publish.

#### 3. A killed `shipvo sim` can leave its server running (seen once, not reproduced)

I stopped the first simulator with a `pkill` that also ended my shell. Port 4545 stayed taken by `node .../@shipvo/sim/server.mjs --port 4545 --app habits`. The next `npm run sim` printed the clear port message, but my tests ran against the old server and failed with `simulator /session answered 500. Is it running at http://localhost:4545? Start it with: npx shipvo sim`. The message says "is it running", but it was. I do not know why `/session` answered 500, and I did not try to reproduce it, so no issue is filed.

#### Smaller notes

- `vitest` prints `The CJS build of Vite's Node API is deprecated` on every run (also in run 1).
- The scaffold `package.json` has no `@shipvo/mcp` dependency, so local MCP driving needs `npx -y @shipvo/mcp`; I installed the tarball instead.
- `publish` printed `native modules not recorded ... @shipvo/runtime@file:../../tarballs/...`. That comes from the tarball install and a normal user would not see it.

### Not covered

Location, notifications and payments were not used in my app. Android emulator and iOS Simulator runs, store builds, hosted control plane, `shipvo login` and a real rollback were not tried. I did not check over MCP that the scan result reached the list; the vitest test did, with `waitFor("Stretch · 0 day streak")`.

The error is accurate, but nothing in `getting-started.md` says `tests/app.test.ts` tests the starter screen. A newcomer replacing `App.tsx` will see red tests they did not write. I added one sentence to the doc. I deleted nothing: I ran only `tests/habits.test.ts`.

### 2. `device_log` on an unknown session returns an empty log (issue #194)

```
## device_log {"session":"m1"}
{ "note": "Everything here is simulated: ...", "log": [] }
## screen {"session":"m1"}
Error: no session 'm1': call /session first ...
```

I made this mistake myself: I assumed I could choose the session id, but `open_app` returns it (`habits-mw3h2i14`). Every other tool errored clearly. `device_log` said the app did nothing. Cause: `packages/mcp/src/server.ts:166` does not check `ok`.

Also seen: after `tap` opened the fingerprint dialog, `device_log` had an empty `log`. I did not check whether prompts are logged before they are answered, so I make no claim.

### 4. The measured times in `getting-started.md` read as the whole path (fixed in this PR)

The doc says `publish --dry-run` took 107 ms. That run uses `--skip-export`. With the real export, on this runner:

| Command | Time |
| --- | --- |
| `shipvo publish --dry-run` (first run, cold Metro cache, prints `Bundler cache is empty, rebuilding`) | 18.8 s |

The doc does say export was not timed, but a newcomer will think the command is instant. I replaced the sentence with these numbers. Also: `--skip-web true` saves about 6 s, so "run faster" is true but small.
