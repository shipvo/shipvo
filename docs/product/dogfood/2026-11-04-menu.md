# Dogfood 2026-11-04: restaurant menu and table ordering

**Persona:** an experienced React Native developer who has never used Shipvo.
**App:** "Table Menu". Scan a table QR code, pick dishes, confirm with a fingerprint, pay by mobile money, get a notification.
**Code under test:** `main` at the start of this branch. Packages built from source and packed with `pnpm pack`, then installed into `/tmp/agent/app/menu` from the tarballs.
**Device features used:** camera scan, biometrics, payment, notifications (four of the five in `docs/device-api.md`).

## Steps and times

| Step | What I did | Time |
| --- | --- | --- |
| Build repo packages | `pnpm install --frozen-lockfile`, schema build, `pnpm -r --filter "./packages/**" build` | 14 s |
| Install CLI | `npm i` the cli and schema tarballs | 1 s |
| 1. Create | `shipvo init menu --name "Table Menu"` | 1 s |
| 1. Install | `npm install` with all 7 tarballs (604 packages) | 27 s |
| 1. Browser | `npx playwright install chromium` | 8 s |
| 2. Simulator | `npm run sim`, until `/app/` answered | 8 s |
| Scaffold tests | `npx vitest run`: 5 passed | 10 s |
| Build the app | wrote `App.tsx`, `src/menu.ts`, `tests/menu.test.ts` (about 100 lines); `tsc --noEmit` clean | not timed |
| My tests | `npx vitest run tests/menu.test.ts`: 2 passed | 9 s |
| MCP drive | `list_apps`, `open_app`, `set_device`, `screen`, `tap`, `device_log`, `screenshot` over stdio | see friction 1 |
| Maintenance | edited `src/release.ts`, ran `shipvo publish --dry-run` and `shipvo rollback` | see friction 2 |

**Time to a first running app:** about 45 s after the packages were built (1 + 1 + 27 + 8 + 8), 59 s with the build.
**Time to a first passing test:** about 55 s (45 s plus the 10 s scaffold test run). My own two menu tests passed after the app was written.

The tarball install replaces `npm install` of the published packages, so the 27 s includes no registry fetch of `@shipvo/*`.

## What worked

- `shipvo init` produces a complete app that type-checks and passes its 5 scaffold tests with no edits.
- The simulator showed my screens as an accessibility tree with stable refs. Permission dialogs for the camera and the fingerprint appeared in the tree and the tests answered them by name.
- `@shipvo/test` read well. My failure-path test (declined payment) was a copy of the pattern in `docs/testing.md` with my labels, and it passed first time. `payment: { nextResult: "decline" }` produced `Payment failed: declined` in the app.
- `device_log` marks every event `simulated: true` and `capabilities` reports `simulated`, as the docs promise.
- `set_device` for a QR code worked: the app showed `Table 12` after the scan.
- `tsc --noEmit` accepted `device.pay.charge`, `device.auth.confirm` and `device.camera.scan` as written in the docs.

## Friction

### 1. Local MCP cannot open the app the docs tell you to open (issue #25)

Docs (`getting-started.md` step 2): `open_app("myshop")`. What happened, with `PN_SIM=http://localhost:4545`:

```
list_apps -> tide: Tide & Tackle. Fishing-supplies shop in Douala ... (open_app("tide@latest"))
open_app {"app":"menu"} -> unknown app "menu". Apps: tide
```

`packages/mcp/src/server.ts:19` hard-codes `tide` unless the undocumented `PN_APPS` JSON env var is set. With `PN_APPS` it works. I expected the server to open the app the simulator serves. Also, `shipvo mcp` answered `Not signed in. Run `shipvo login`.` when I wanted the local config.

### 2. No way to check a release locally (issue #26)

```
$ npx shipvo publish --dry-run
Nothing to publish with. Hosted: run `shipvo login`, then `shipvo app create` (or set SHIPVO_PUBLISH_TOKEN). Self-hosted: set CLOUDFLARE_ACCOUNT_ID, CLOUDFLARE_API_TOKEN and SHIPVO_KV_ID.
```

`--dry-run` is ignored, and `rollback` gives the same message. I could not see whether my release builds, how big it is, or what would be signed. This step of the dogfood brief (prepare a release, roll back) is **not proven**: I did not run a Hermes build, a patch, a signature or a rollback. I did not try `SHIPVO_PUBLISH_TOKEN` because the only control plane it can reach is production.

### 3. `shipvo sim` twice: success message, then a raw crash (issue #27)

Running `npm run sim` again after an edit rebuilt the bundle (about 6 s), printed `Simulator on http://localhost:4545`, then died with `Error: listen EADDRINUSE: address already in use :::4545` and a Node stack. The failed run had already replaced `sim-dist/`, so the old server then served the new code. There is no watch mode, so every edit needs a stop, start and 8 s wait.

### 4. Small notes (no issue)

- After `tap` on "Scan table code" and the permission, the tree still shows the camera viewfinder. The scan result arrives a moment later, so an agent that reads the screen straight away sees an unfinished scan. Reading `screen` again showed `Table 12`. Worked as designed, but `getting-started.md` could say "read the screen again after a scan".
- `getting-started.md` says "Twenty minutes". The measured path to a running app was under a minute here. Nothing is wrong, but the estimate is not from a measurement.
