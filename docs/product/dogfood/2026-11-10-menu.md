# Dogfood 2026-11-10: restaurant menu and table ordering, as a non-technical founder

**Persona:** a non-technical founder who works only through an AI agent. The founder says what they want; the agent runs the CLI, the MCP tools and the tests.
**App:** "Table Menu". The customer scans the QR code on the table, picks dishes, pays with mobile money and gets a notification.
**Code under test:** `main` at `e26369bc`. Packages built from source with `pnpm -r --filter "./packages/**" build`, packed with `pnpm pack`, installed into `/tmp/agent/app/menu` from the tarballs (`overrides` in `package.json` point every `@shipvo/*` package at its tarball).
**Starting point:** `shipvo init menu --name "Table Menu" --template shop`. The founder's content is `src/data/products.json` (the dishes and prices).
**Device features used:** camera scan (table QR code), payment (mobile money), notifications (order confirmed). Location and biometrics were not used.

## What worked

- The last report's two blockers are fixed. `open_app("menu")` opens the app the local simulator serves (`list_apps` answered `menu: Table Menu. The app this simulator serves.`). `shipvo publish --dry-run` and `shipvo rollback --to 1 --dry-run` run with no login: the publish wrote the bundle, 3 signed pointers and release records to `.shipvo/dry-run` (release size 1.70 MB), and the rollback printed `Offline rehearsal: reading releases from .shipvo/dry-run`, `New release number: 3`, `Bands: b0, b1, b2`.
- `shipvo sim --watch` rebuilds in 1.3 to 1.5 s and keeps serving. The scan fix and the new button went live without a restart.
- A founder's content change needs no code. Replacing the dishes in `src/data/products.json` kept all 12 starter tests green, because those tests read names and prices from the same file.
- `@shipvo/test` failure messages are good. When my test forgot the camera permission, the error printed the screen with the `Allow Table Menu to take pictures and record video?` dialog and its three buttons, and I could see what to tap. When the simulator answered 500 it said `Is it running at http://localhost:4545? Start it with: npx shipvo sim`.
- Camera scan, permission dialog, payment decline and notifications behave as `docs/device-api.md` says. `device_log` showed the `permission` (granted) and `scan` (`qr`, `TABLE-12`) entries, each `simulated: true`, and `capabilities` listed every capability as `simulated`.
- `shipvo doctor` printed 12 PASS lines and no warnings.

## Friction

### 1. SIGTERM leaves a dead simulator server on the port (issue #1575)

I stopped a simulator with `kill <pid>`. The Chromium closed, the server kept listening, and every new session answered 500:

```
$ kill -TERM <pid of node_modules/@shipvo/sim/server.mjs>
$ curl -s -X POST localhost:4547/session -H 'content-type: application/json' -d '{"session":"b","app":"menu"}'
{"error":"Error: browser.newContext: Target page, context or browser has been closed"}   (HTTP 500)
$ npx shipvo sim --watch
Port 4545 is in use. Stop the other `shipvo sim` or pass --port <n>.
```

Ctrl-C (SIGINT) stops it correctly. I expected SIGTERM to do the same. An agent that starts and stops the simulator in the background stops it with SIGTERM, so this is the way a founder's agent gets stuck. It cost me one failed test run and a `kill -9`.

### 2. The shop template does not type-check (issue #1576)

```
$ npm run typecheck
tests/app.test.ts(62,41): error TS2322: Type 'string' is not assignable to type '"timeout" | "insufficient_funds" | "cancel" | "approve" | "decline" | undefined'.
```

The file is the one `shipvo init --template shop` wrote. The test itself passes. I expected a fresh app to be clean.

### 3. Tests with no simulator running print a raw network error (issue #1577)

```
$ npx vitest run      # before npm run sim
 Tests  11 failed | 1 passed (12)
Serialized Error: { errors: [ { message: 'connect ECONNREFUSED ::1:4545' ... }, { message: 'connect ECONNREFUSED 127.0.0.1:4545' ... } ], code: 'ECONNREFUSED' }
MaxListenersExceededWarning: ... 11 unhandledRejection listeners added to [process].
```

The test file's first comment says to start `npm run sim` first, and the failure for a 500 has a clear message. I expected the same plain message here.

### 4. Doc fixed in this PR

`docs/getting-started.md` said `shipvo rollback --to <n> --dry-run` "still needs access to the control plane or KV ... so it is not offline". With no login it reads `.shipvo/dry-run` and prints `Offline rehearsal` (see `packages/cli/src/publish.ts:321`). I changed the sentence to say both cases.

### 5. Small notes (no issue)

- `tap` takes a `ref`, not a name. Passing `name` gives `MCP error -32602: ... Required at ref`. The agent needs a `screen` call first. This is as documented.
- After a scan the tree can still show the camera dialog for about a second. `screen` again shows the result. `tests` should use `waitFor`.
- `shipvo agents setup` failed here with `EOVERRIDE` because my `package.json` has a tarball `overrides` entry for `@shipvo/mcp`. That is an artefact of the local-tarball setup and not a product bug. I installed the mcp tarball directly.
- My first CLI install used only two tarballs, so npm fetched an older `@shipvo/store` from the registry and `shipvo` crashed on a missing export (`renderPolicyText`). That is a mistake in my setup (all tarballs must be installed together), not a product bug.
