- **MCP: tool annotations and `isError`.** Every tool now declares annotations. `list_apps`, `list_sessions`, `screen`, `screenshot`, `notifications`, `device_log` and `owner_describe` set `readOnlyHint: true`; `owner_command` and `end_session` set `destructiveHint: true`; the rest are not read-only. When the simulator reports `ok: false`, the result now has `isError: true` and `structuredContent` `{ ok, code, error }`. The text (`Error [code]: ...`) is unchanged. Tool names and arguments are unchanged. Migration: none needed. Clients that branched on the text can now branch on `isError`.

- **Control plane: `GET /t/:app/summary`.** Returns `{ releases: [{ release, events: { <event>: n }, apply_ms_median, cold_start_ms_median }] }` for the 20 newest releases (by latest row), so you can see applied, healthy and reverted counts without reading raw rows. Same access as `GET /t/:app`. A median is `null` when no row has that value. No migration. Migration: none needed.

- **Android: a release that throws after `markHealthy` is now reverted.** React destroys the host after an uncaught JS error, and the activity pause that follows was counted as a clean trip to the background, which cleared the unhealthy-boot count. `markHealthy` now installs a JS error hook that tells the native runtime first, and that load can no longer become stable. No JS API change. Migration: rebuild the shell to get the native `noteCrash` function; older shells keep the old behaviour.

- **MCP actions say what changed.** `tap`, `type`, `scroll` and `back` now start their result with `Change: none`, `content changed`, `new screen`, `scrolled` or `unknown` (no earlier screen for that session id), computed by comparing the new tree with the session's previous one. `type` also adds `Value of <ref>: "..."`, the field's value after typing. The full tree is still returned. New optional `compact: true` on these four tools: when the change is `content changed`, the result lists only added (`+`) and removed (`-`) lines; refs are the ones on the new screen. Migration: none needed. Clients that parse the result now see the extra lines first.

- **Open a deep link in the running app: `phone.openUrl(url)` and MCP `open_url`.** The URL reaches the app through `onUrl` from `@shipvo/device` (new). On a phone it wraps `Linking`. In the simulator, `openUrl` calls it and still fires the `pn:url` window event. If the app has no `onUrl` listener, the simulator answers `{ ok: false, code: "no_url_listener" }`. `phone.openUrl` then throws `PhoneError` (new export of `@shipvo/test`, with `code`), and `open_url` shows `Error [no_url_listener]`. `open_url` is annotated not read-only, not destructive, not idempotent, closed world. Migration: none needed. To be testable, subscribe with `onUrl`.

- **Rollback now catches releases that crash after `markHealthy`.** `markHealthy` still means "first screen rendered" and still promotes a staged release. The runtime now clears its unhealthy-boot count only after the app stays in the foreground for 30 s, or goes to background. A release that crashes inside that window counts as an unhealthy boot, so the existing rule (3 boots in 60 s, then revert with `crash_loop_revert`) applies to it. No JS API change. A good release that you open and kill in the foreground within 30 s, 4 times in 60 s, is reverted too. Reverting does not undo changes the bad release made to app storage. Migration: none needed.

- **`shipvo rollback --to <n> --dry-run`.** Reads the bundle of release `<n>`, prints a summary (new release number, platforms, bands, min shell version) and writes nothing. It still needs your config and access to the control plane or KV to read the bundle, so unlike `publish --dry-run` it is not offline. A missing bundle still exits 1. Without the flag, output and behaviour are unchanged. Migration: none needed.

- **`@shipvo/mcp` HTTP is stateless; scope is per request.** `shipvo-mcp --http` no longer keeps MCP sessions. Each POST builds its own server from that request's `x-shipvo-*` headers, so a `read` request cannot use an earlier `owner` request's scope. `tools/list` and `tools/call` work with no `Mcp-Session-Id` and no `initialize` (the 2026-07-28 shape); 2025-era clients that initialize still work. Migration: `GET` and `DELETE` on `/mcp` now answer 405 (they were 400 without a session), `initialize` no longer returns an `Mcp-Session-Id`, and `/health` no longer reports `sessions`. Simulator sessions are unchanged. Not yet done: `server/discover`, `Mcp-Method`/`Mcp-Name` headers, `ttlMs`/`cacheScope`.

- **Stale element refs are an error, never a wrong tap.** `/act` in `@shipvo/sim` now checks a ref before `tap`, `type` and `scroll`. If the element was re-rendered with new content, is gone, or the ref came from an earlier page load, the answer is `{ ok: false, code: "stale_ref", error: "stale ref e5: the screen changed. Take a new snapshot (action \"screen\") and use a ref from it." }`. Before, a re-rendered element waited 3 seconds and failed with a Playwright timeout, and a ref from before a page load could hit a different element. `@shipvo/mcp` shows it as `Error [stale_ref]: ...` followed by the new screen. Refs after a full page load now look like `p1e5` (they were `e5`); refs on the first page and in single-page navigation are unchanged. Treat refs as opaque strings. Migration: on `stale_ref`, read the screen in the same reply and use a ref from it. Tool names and inputs are unchanged.

- **`shipvo publish --dry-run` prints a plain summary; `shipvo publish --help` lists the flags.** The dry run now ends with the release number, size (KB below 1 MB, otherwise MB), the output folder and "Nothing was sent", instead of one line of JSON. The bsdiff4 (pip) hint shows only when older releases exist to patch from. Migration: a script that parsed the JSON from `--dry-run` should read the files in the `--out` directory instead. A real publish still prints JSON.
- **bsdiff patches on iOS.** The iOS runtime now applies BSDIFF40 patches listed in the signed pointer when the patch starts from the bundle the device is running. It checks the patch hash, then the rebuilt bundle's signed hash and size, and falls back to the full bundle on any problem. `shipvo publish --platform ios` now publishes patches from earlier iOS releases (stored as `b/<app>/ios-d-*.bsdiff`). Migration: nothing is required. Pointers without `patches` still work. There is no patch from the app's embedded bundle on iOS yet, so the first update after install is a full download.

- **`shipvo verify <pointer> [public-key]`.** Checks the signature of a release pointer (`{body, signature}`, such as the files `publish --dry-run` writes) and prints `valid` or `INVALID`. The key defaults to the one from your signing seed. `verify-json` is unchanged and still checks `signDoc` documents only. Migration: none needed.
- **`shipvo publish --dry-run`.** Builds the bundle, makes patches (none offline), signs the pointers and writes everything to a local directory (`--out <dir>`, default `.shipvo/dry-run`). It needs only the signing seed: no login, token or Cloudflare variables, and nothing is sent anywhere. Release is 1 unless you pass `--release N`. `shipvo rollback --dry-run` is listed in the entry above. `shipvo publish` and `shipvo rollback` now fail on unknown flags instead of ignoring them. Migration: a script that passed a misspelled or unsupported flag will now fail; remove the flag.
- **Shells declare their Hermes bytecode versions.** `ShellManifest` has an optional `hermes_bytecode_versions` (a non-empty list of positive integers). The control plane pointer route takes an optional `?hbc=96,98` query. If the release sets `hermes_bytecode_version` and it is not in the list, the route answers 404 `hermes_bytecode_mismatch` and the release is not offered. Releases or shells without the field behave as before. Migration: none needed. To opt in, add the field to your shell manifest; the runtime does not send `?hbc=` yet (next slice).
- **CLI:** new `shipvo doctor` command to check setup before first publish. It verifies Node version, `shipvo.json` parsing, signing key/public key match, control plane reachability, and validates `hermesBytecodeVersion` when present. It prints one pass/fail line per check with a fix and exits non-zero on any failure.
- **Publish records the Hermes bytecode version.** `shipvo publish` reads the version from the `.hbc` header and adds an optional `hermes_bytecode_version` to the signed release. Set `hermesBytecodeVersion` (a number or list) in `shipvo.json`, or pass `--hermes-bytecode-version`, to make publish fail when the bundle is plain JavaScript or built with a different Hermes. Migration: nothing is required. Releases without the field still parse and apply as before. Shells do not check the field yet; that is a follow-up.
