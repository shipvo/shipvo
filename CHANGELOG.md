# Changelog

Dated, newest first. Package versions are on npm under `@shipvo`.

## Unreleased

- **@shipvo/mcp**: new read-only tool `export_test(session)` returns a `@shipvo/test` script for the session's steps (`openApp`, `tap`, `type`, `scroll`, `back`, `device.set`, and a `waitFor` after steps that changed the screen). Targets are visible text, not refs. An ambiguous target becomes a `// TODO: ambiguous` comment; values typed into password-like fields and `payment.pin` become `process.env.SHIPVO_TEST_*` placeholders. An unknown session gives error code `no_session`. Migration: none; no existing tool changed.
- **control-plane, @shipvo/cli: a halted release shows in `GET /t/:app/summary` and `shipvo status`.** The summary has a new optional top-level field `halted`: the `halt/<app>` object (`release`, `halted_at`, `reports`, `failed`, `threshold`) or `null`. `shipvo status` prints one line above the table when it is set: `Release <n> is halted: <failed> of <reports> devices failed (limit <threshold%>). Publish a new release or run shipvo rollback to clear.` `--json` passes the field through. Output is unchanged when `halted` is null or missing (older control planes). Migration: none.
- **@shipvo/cli**: new module `adopt-bare` (slice 1 of #201, not yet wired into `shipvo init`): `writeAndroidConfig` adds or updates the `dev.shipvo.*` meta-data in a bare app's `AndroidManifest.xml` as `app.plugin.js` does, `checkExpoModules` reports whether Expo Modules are set up and returns the step `npx install-expo-modules@latest` (never run), and `findAndroidManifest` locates the file. Migration: none; additive.
- **@shipvo/cli**: new `src/adopt-bare.ts` (not wired into `shipvo init` yet) with `writeIosConfig`, `findIosInfoPlist` and `adoptNextSteps` for bare React Native apps. `writeIosConfig` sets `ShipvoBaseURL`, `ShipvoPublicKey`, `ShipvoAppId`, `ShipvoShellMajor` (and optional `ShipvoHermesBytecodeVersions`, `ShipvoNativeModules`) in Info.plist, the same values as `app.plugin.js`; other keys keep their order and a second run changes nothing. Adds the `plist` dependency. Migration: none.
- **control-plane: the pointer endpoint answers 404 `release_halted` for a halted release.** Only when KV `halt/<app>` exists and holds the same `release` as the pointer. Body: `{ "error": "release_halted", "release": n }`, with `cache-control: public, max-age=5`. Shells keep their current release on a 404. A halt for release 5 does not affect release 6, and a corrupt `halt/<app>` value is ignored. Migration: none.
- **@shipvo/mcp, control-plane, @shipvo/cli**: owner commands that cannot be undone (`publish`, price changes in `update_product`, `remove_product`, `upsert_promo`, `set_promo_active`, `remove_home_block`, `discard_draft`, `create_api_key`, `revoke_api_key`) now need `confirm: true` when an agent calls them with the owner token. Without it nothing runs and the result is `{ ok: false, code: "needs_confirm", plan: string[] }`; the plan says what changes and how many update reports the server has received before a publish (the number of phones is not known). New `owner_command` argument `confirm`. New `agentPolicy` (`ask` default, `deny`, `allow`) and `agentDeny` in `shipvo.json` and in the control plane (`get_agent_policy`, `set_agent_policy`, owner sign-in only); calls that ran after `confirm: true` are logged with `"confirmed": true`, refused calls with `"denied": true`, and `set_agent_policy` changes are logged. An `args.confirm` from the agent is ignored by the MCP server unless the top-level `confirm` is true. The signed-in admin is not gated. Migration: agents that publish or change prices must call again with `confirm: true`; set `agentPolicy` to `allow` only if you want the old behaviour.
- **@shipvo/runtime (iOS) and @shipvo/cli: the first iOS update can be a patch against the app's embedded bundle.** The iOS runtime hashes `main.jsbundle` and uses it as the patch base when the signed pointer lists a patch from that hash. The patch hash, the rebuilt bundle's size and hash are checked as before; any problem falls back to the full bundle. `shipvo publish --platform ios` builds a patch from each iOS shell base record under `base/<app>/` (records with `"platform": "ios"`; records without `platform` stay Android-only). Migration: none for apps; register an iOS shell's embedded bundle in KV the way `build-shell.yml` does for Android, with `platform: "ios"`.
- **@shipvo/test, @shipvo/sim**: new `phone.mockNetwork(rules)` and `phone.clearNetworkMocks()` stub `fetch` and XHR responses in the simulator page. A rule has `url` (string or RegExp), optional `method`, and `status`, `body`, `headers`, `delayMs`. Unmatched requests pass through. A bad rule throws `PhoneError` with code `mock_invalid`. The sim has a new action, `set_network_mocks`, and a new file, `mock-rules.mjs`. Migration: none; additive.
- **@shipvo/device, @shipvo/test, @shipvo/mcp**: new `contacts` capability. `device.contacts.getAll()` reads the address book (read-only); permissions accept `"contacts"`; `capabilities()` gains `contacts` (`real` with `expo-contacts`, `simulated` in the simulator, else `unavailable`). In the simulator, `phone.contacts.set([...])` in `@shipvo/test` (or `contacts` in the MCP `set_device` tool) seeds the address book, a permission dialog is shown, and a refusal throws `Contacts permission denied`, as on a phone. `withShipvoSim` also aliases `expo-contacts`. Migration: none; code that builds a `Device` object by hand needs a `contacts` member and a `contacts` entry in `capabilities()`.
- **@shipvo/cli**: `shipvo init` takes `--template blank|content` (default `blank`, output unchanged). `content` writes a list screen, a detail screen, `src/data/articles.json` and a matching simulator test. An unknown name prints the valid names and exits 2. Migration: none.
- **@shipvo/cli**: new command `shipvo status [--app <id>] [--json]` reads `/t/<app>/summary` from the control plane in `shipvo.json` and prints event counts and median apply and cold start times for the newest releases. Prints "No telemetry yet" when empty; exits 1 with a plain message when the control plane is unreachable. Migration: none.
- **@shipvo/schema, control-plane, sample app**: `Telemetry.event` accepts `hermes_bytecode_mismatch`, `native_module_missing` and `native_module_version`, so `POST /t` returns 202 for them and `GET /t/:app/summary` counts them per release. The sample app forwards `hermes_bytecode_mismatch:<release>:...` under that release and `pointer_rejected:<reason>` for the two native-module reasons; other reasons are ignored. No migration for the `event` column (text). Migration: code that switches exhaustively on the `Telemetry` event type should handle the three new values; old clients keep working.
- **@shipvo/cli**: `shipvo doctor` has two new checks. It fails when the signing key file is readable by group or others (skipped on Windows, and when the seed comes from an environment variable), and when `<controlPlane>/health` does not answer HTTP 200 with JSON (5 second timeout). Each failure prints a one-line fix. Migration: none; `shipvo doctor` can now exit non-zero for setups that passed before.
- **@shipvo/cli**: `shipvo doctor` now checks that Playwright Chromium is installed (fix: `npx playwright install chromium`) and that the sim port is free (default 4545, or `--port <n>`; fix: `Stop the other process or pass --port <n>`). Both run offline and are skipped when `package.json` has no `sim` script. Migration: none; `doctor` now accepts `--port`.
- **@shipvo/cli**: `shipvo doctor` accepts `--offline` (skips the control-plane reachability and `/health` checks, which then print PASS with a skipped note) and `--skip-sim` (skips the Chromium and sim port checks). Migration: none; both are optional.
- **@shipvo/runtime**: Android and iOS shells now refuse a release whose `hermes_bytecode_version` differs from the Hermes bytecode version of the shell's embedded bundle. The release is discarded and the current release keeps running. `consumeEvents()` returns `hermes_bytecode_mismatch:<release>:release=<n>:shell=<m>`, and `checkForUpdate` returns `{ status: "none", reason: "hermes_bytecode_mismatch" }`. A missing field on the release, or an embedded bundle that is not Hermes bytecode, means the release is applied as before. This runs in addition to the signature and hash checks. Migration: none; `CheckResult` gains an optional `reason`.

## Unreleased

- **Runtime (Android): sends `?hbc=` and `?nm=` with the pointer request.** The shell reads `dev.shipvo.HERMES_BYTECODE_VERSIONS` (for example `96,98`) and `dev.shipvo.NATIVE_MODULES` (for example `react-native-mmkv@3.1.0,@scope/pkg@1.0.0`) from its manifest meta-data and adds them to the pointer URL, URL-encoded, only when present. A 404 with `hermes_bytecode_mismatch`, `native_module_missing` or `native_module_version` keeps the current release; `checkForUpdate` returns `{ status: "none", reason }` and the event `pointer_rejected:<reason>` is queued locally once per reason until `consumeEvents()` runs. It is not sent to telemetry yet: `/t` does not accept it and the sample app does not forward it. Migration: none needed; shells without the meta-data send the same URL as before. iOS is the next slice.
- **Config plugin: declare Hermes bytecode versions and native modules.** `@shipvo/runtime/app.plugin.js` takes optional `hermesBytecodeVersions` (array of integers) and `nativeModules` (package name to version). Android gets meta-data `dev.shipvo.HERMES_BYTECODE_VERSIONS` (`96,98`) and `dev.shipvo.NATIVE_MODULES` (`name@version,...`); iOS gets `ShipvoHermesBytecodeVersions` and `ShipvoNativeModules` in Info.plist, same format. A non-integer version or an empty package name throws. Omitted props write nothing. Migration: none needed. The runtime does not read or send these yet (next slices).

- **MCP: simulator calls have a time limit.** Every call from `@shipvo/mcp` to the simulator now stops after 30 s (set `SHIPVO_SIM_TIMEOUT_MS` to change it). On timeout the tool returns `isError: true` with code `sim_timeout` (same shape as other simulator errors: `structuredContent` `{ ok, code, error }`) and says the action may still have run, so the agent should call `screen`. Timed-out actions are not retried. Migration: none needed.

- **Native module safety (first slice).** `ShellManifest` has an optional `native_modules` (package name to version). `ReleasePointer` has an optional `required_native_modules` (package name to semver range). `@shipvo/schema` exports `satisfiesRange` and `checkNativeModules`. `shipvo publish` records the `package.json` dependencies that have native code and prints them in `--dry-run`. The pointer route takes an optional `?nm=name@1.2.3,...`; when both sides are known it answers 404 `native_module_missing` or `native_module_version` instead of offering the release. Migration: none needed, all fields are optional and old payloads parse. The runtime does not send `?nm=` yet (next slice).

- **CLI: `shipvo sim --watch`.** Rebuilds the web bundle when project files change (300 ms debounce; ignores `node_modules`, `sim-dist`, `.shipvo`, `.git`, `.expo`, `dist`, `dist-ota`, `web-build`, `ios`, `android`) and keeps the same server and port. Prints one line per rebuild. A failed build prints the error and keeps serving the last good build. Without `--watch` nothing changes. Migration: none needed.

- **MCP: tool annotations and `isError`.** Every tool now declares annotations. `list_apps`, `list_sessions`, `screen`, `screenshot`, `notifications`, `device_log` and `owner_describe` set `readOnlyHint: true`; `owner_command` and `end_session` set `destructiveHint: true`; the rest are not read-only. When the simulator reports `ok: false`, the result now has `isError: true` and `structuredContent` `{ ok, code, error }`. The text (`Error [code]: ...`) is unchanged. Tool names and arguments are unchanged. Migration: none needed. Clients that branched on the text can now branch on `isError`.

- **Control plane: `GET /t/:app/summary`.** Returns `{ releases: [{ release, events: { <event>: n }, apply_ms_median, cold_start_ms_median }] }` for the 20 newest releases (by latest row), so you can see applied, healthy and reverted counts without reading raw rows. Same access as `GET /t/:app`. A median is `null` when no row has that value. No migration. Migration: none needed.

- **Android: a release that throws after `markHealthy` is now reverted.** React destroys the host after an uncaught JS error, and the activity pause that follows was counted as a clean trip to the background, which cleared the unhealthy-boot count. `markHealthy` now installs a JS error hook that tells the native runtime first, and that load can no longer become stable. No JS API change. Migration: rebuild the shell to get the native `noteCrash` function; older shells keep the old behaviour.

- **MCP actions say what changed.** `tap`, `type`, `scroll` and `back` now start their result with `Change: none`, `content changed`, `new screen`, `scrolled` or `unknown` (no earlier screen for that session id), computed by comparing the new tree with the session's previous one. `type` also adds `Value of <ref>: "..."`, the field's value after typing. The full tree is still returned. New optional `compact: true` on these four tools: when the change is `content changed`, the result lists only added (`+`) and removed (`-`) lines; refs are the ones on the new screen. Migration: none needed. Clients that parse the result now see the extra lines first.

- **Open a deep link in the running app: `phone.openUrl(url)` and MCP `open_url`.** The URL reaches the app through `onUrl` from `@shipvo/device` (new). On a phone it wraps `Linking`. In the simulator, `openUrl` calls it and still fires the `pn:url` window event. If the app has no `onUrl` listener, the simulator answers `{ ok: false, code: "no_url_listener" }`. `phone.openUrl` then throws `PhoneError` (new export of `@shipvo/test`, with `code`), and `open_url` shows `Error [no_url_listener]`. `open_url` is annotated not read-only, not destructive, not idempotent, closed world. Migration: none needed. To be testable, subscribe with `onUrl`.

- **Rollback now catches releases that crash after `markHealthy`.** `markHealthy` still means "first screen rendered" and still promotes a staged release. The runtime now clears its unhealthy-boot count only after the app stays in the foreground for 30 s, or goes to background. A release that crashes inside that window counts as an unhealthy boot, so the existing rule (3 boots in 60 s, then revert with `crash_loop_revert`) applies to it. No JS API change. A good release that you open and kill in the foreground within 30 s, 4 times in 60 s, is reverted too. Reverting does not undo changes the bad release made to app storage. Migration: none needed.

- **`shipvo rollback --to <n> --dry-run`.** Reads the bundle of release `<n>`, prints a summary (new release number, platforms, bands, min shell version) and writes nothing. It still needs your config and access to the control plane or KV to read the bundle, so unlike `publish --dry-run` it is not offline. A missing bundle still exits 1. Without the flag, output and behaviour are unchanged. Migration: none needed.

- **`@shipvo/mcp` HTTP is stateless; scope is per request.** `shipvo-mcp --http` no longer keeps MCP sessions. Each POST builds its own server from that request's `x-shipvo-*` headers, so a `read` request cannot use an earlier `owner` request's scope. `tools/list` and `tools/call` work with no `Mcp-Session-Id` and no `initialize` (the 2026-07-28 shape); 2025-era clients that initialize still work. Migration: `GET` and `DELETE` on `/mcp` now answer 405 (they were 400 without a session), `initialize` no longer returns an `Mcp-Session-Id`, and `/health` no longer reports `sessions`. Simulator sessions are unchanged. Not yet done: `server/discover`, `Mcp-Method`/`Mcp-Name` headers, `ttlMs`/`cacheScope`.

- **Stale element refs are an error, never a wrong tap.** `/act` in `@shipvo/sim` now checks a ref before `tap`, `type` and `scroll`. If the element was re-rendered with new content, is gone, or the ref came from an earlier page load, the answer is `{ ok: false, code: "stale_ref", error: "stale ref e5: the screen changed. Take a new snapshot (action \"screen\") and use a ref from it." }`. Before, a re-rendered element waited 3 seconds and failed with a Playwright timeout, and a ref from before a page load could hit a different element. `@shipvo/mcp` shows it as `Error [stale_ref]: ...` followed by the new screen. Refs after a full page load now look like `p1e5` (they were `e5`); refs on the first page and in single-page navigation are unchanged. Treat refs as opaque strings. Migration: on `stale_ref`, read the screen in the same reply and use a ref from it. Tool names and inputs are unchanged.

- **`shipvo publish --dry-run` prints a plain summary; `shipvo publish --help` lists the flags.** The dry run now ends with the release number, size (KB below 1 MB, otherwise MB), the output folder and "Nothing was sent", instead of one line of JSON. The bsdiff4 (pip) hint shows only when older releases exist to patch from. Migration: a script that parsed the JSON from `--dry-run` should read the files in the `--out` directory instead. A real publish still prints JSON.
- **bsdiff patches on iOS.** The iOS runtime now applies BSDIFF40 patches listed in the signed pointer when the patch starts from the bundle the device is running. It checks the patch hash, then the rebuilt bundle's signed hash and size, and falls back to the full bundle on any problem. `shipvo publish --platform ios` now publishes patches from earlier iOS releases (stored as `b/<app>/ios-d-*.bsdiff`). Migration: nothing is required. Pointers without `patches` still work. There is no patch from the app's embedded bundle on iOS yet, so the first update after install is a full download.

- **`shipvo verify <pointer> [public-key]`.** Checks the signature of a release pointer (`{body, signature}`, such as the files `publish --dry-run` writes) and prints `valid` or `INVALID`. The key defaults to the one from your signing seed. `verify-json` is unchanged and still checks `signDoc` documents only. Migration: none needed.
- **`shipvo publish --dry-run`.** Builds the bundle, makes patches (none offline), signs the pointers and writes everything to a local directory (`--out <dir>`, default `.shipvo/dry-run`). It needs only the signing seed: no login, token or Cloudflare variables, and nothing is sent anywhere. Release is 1 unless you pass `--release N`. `shipvo rollback --dry-run` is listed in the entry above. `shipvo publish` and `shipvo rollback` now fail on unknown flags instead of ignoring them. Migration: a script that passed a misspelled or unsupported flag will now fail; remove the flag.
- **Shells declare their Hermes bytecode versions.** `ShellManifest` has an optional `hermes_bytecode_versions` (a non-empty list of positive integers). The control plane pointer route takes an optional `?hbc=96,98` query. If the release sets `hermes_bytecode_version` and it is not in the list, the route answers 404 `hermes_bytecode_mismatch` and the release is not offered. Releases or shells without the field behave as before. Migration: none needed. To opt in, add the field to your shell manifest; the runtime does not send `?hbc=` yet (next slice).
- **CLI:** new `shipvo doctor` command to check setup before first publish. It verifies Node version, `shipvo.json` parsing, signing key/public key match, control plane reachability, and validates `hermesBytecodeVersion` when present. It prints one pass/fail line per check with a fix and exits non-zero on any failure.
- **Publish records the Hermes bytecode version.** `shipvo publish` reads the version from the `.hbc` header and adds an optional `hermes_bytecode_version` to the signed release. Set `hermesBytecodeVersion` (a number or list) in `shipvo.json`, or pass `--hermes-bytecode-version`, to make publish fail when the bundle is plain JavaScript or built with a different Hermes. Migration: nothing is required. Releases without the field still parse and apply as before. Shells do not check the field yet; that is a follow-up.
